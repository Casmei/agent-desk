# M0 — Fundação: plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** entregar a fundação do `agent-desk`: documentação completa (negócio + técnica), a skill de pareamento `pair-feature`, e um monorepo com API Nest que sobe, responde `/health`, tem banco, logs, testes, lint de camadas, Docker e CI. Nenhuma regra de negócio.

**Arquitetura:** monólito modular em NestJS dentro de um monorepo pnpm + Turborepo. Cada módulo futuro terá as camadas `domain` / `application` / `infrastructure` / `interface`, verificadas por lint. Neste marco só existe a pasta `shared/` (config, logs, banco, redis, health) e a regra de camadas pronta para os módulos que virão.

**Tech stack:** Node 24 · pnpm 10 · Turborepo 2 · TypeScript 6.0 · NestJS 12 · Drizzle ORM 0.45 + drizzle-kit + postgres.js · ioredis · envalid 9 (env) · Zod 4 (entrada da API, a partir do M1) · logger nativo do Nest (`ConsoleLogger`) · Vitest 5 + unplugin-swc · ESLint 10 + typescript-eslint + eslint-plugin-boundaries · Vite 8 + React 19 · Docker + docker-compose · GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-agente-whatsapp-mvp-design.md`. Leia o spec inteiro antes de qualquer tarefa. As tarefas de documentação transformam o spec em documentos; elas **não inventam** comportamento novo.

## Restrições globais

- Código, nomes de arquivo, identificadores, tabelas, logs e commits: **inglês**. Conteúdo dos documentos e descrições de PR: **português** (com acentuação correta).
- Commits em Conventional Commits (`feat:`, `docs:`, `chore:`, `test:`, `ci:`), terminando com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Uma tarefa = um PR = um branch** `m0/<NN>-<slug>` saindo de `main`. Máximo **10 arquivos alterados** por tarefa; não contam `pnpm-lock.yaml` nem arquivos em `apps/api/drizzle/`.
- **TDD** em toda tarefa com código: teste primeiro, ver falhar, implementar o mínimo, ver passar.
- TypeScript fixado em `~6.0.3` (typescript-eslint ainda não suporta TS 7; registrado em ADR).
- Node `24` (`.nvmrc` e `engines`). Pacotes com prefixo `@agent-desk/`.
- Nenhum framework de agente, nenhuma regra de negócio, nenhum módulo de domínio neste marco.
- **Sem abstração "para o futuro":** só criar o que uma tarefa deste plano usa.
- Licença MIT, titular "Tiago de Castro", ano 2026.

## Foco de revisão

Falhas que o spec implica e que mais provavelmente afetam quem usa a fundação. Cada uma tem teste na tarefa dona:

1. **Variável de ambiente ausente ou inválida** → a API não sobe e a mensagem lista **cada** variável inválida pelo nome (Tarefa 11).
2. **Segredo em log** (parâmetros com `authorization`, `x-admin-token`, `apiKey`, `token`, `password`, `secret`) → aparece `[REDACTED]`, nunca o valor (Tarefa 12).
3. **Postgres ou Redis fora do ar** → `/health` responde **503** em até ~2 s dizendo qual está `down`, sem travar (Tarefa 14).
4. **Domínio importando framework ou infraestrutura** (`@nestjs/*`, `drizzle-orm`, `ioredis`, pasta `infrastructure`) → o lint falha (Tarefa 15).
5. **Contagem do limite de PR** → lockfile e migrations não contam; exatamente 10 arquivos passa e 11 avisa (Tarefa 18).
